# V0 双目立体成像执行计划

版本：V0；建立及最近核对日期：2026-10-20；计划状态：活动中，准备阶段。

依据：[算法规格](../../algorithm/algorithm.md)、[硬件说明](../../hardware/hardware.md)、[硬件配置](../../../config/hardware.json)。

## 1. 目标与范围

使用 Python 3.11、OpenCV 和 NumPy，建立“原始双目图像 → 标定 → 校正 → SGBM 视差 → 深度与彩色点云 → 评估”的可复现流程。先支持保存图像的离线处理，再接入真实相机；图像数组、标定参数和配置通过明确的函数接口传递。

本阶段处理固定结构、固定分辨率、水平双目下的静态场景。不扩展学习式匹配、置信度网络、在线自适应、多帧融合、网格重建或 SLAM。

## 3. 并行路线与依赖

```text
                    对齐图像、配置与标定契约
                         /          \
硬件路线：H1 设备确认 → H2 固定与控制 → H3 数据采集
软件路线：A0 环境接口 → A1 离线标定 → A2 校正
                                      → A3 重建 → A4 评估
                         \          /
                  I1 真实数据联调 → I2 独立评价与复现
```

硬件路线由持有设备的协作者与采集适配实现共同推进；本 Agent 负责软件路线及后续算法联调。两条路线可由不同成员并行，不要求同一工作区同时修改同一配置文件。

A1–A4 可以先使用明确来源的离线样例或标记为合成的数据验证程序行为。没有真实棋盘格时，可以验证标定调用、序列化及失败处理，但真实标定质量保持待验证。使用外部数据时保留来源、使用条件、图像处理方式与标定约定，避免把已校正图重复校正。合成验证结果不用于宣称本设备测距精度。

H3 与软件路线通过共享格式对接；硬件不阻塞算法开发，但 I1 需要 H3 与 A1–A4 的必要能力，I2 还需要独立参考距离数据。

## 4. 两条路线的交付契约

### 配置与接口

- `config/hardware.json` 维护硬件规格与已知状态；厂商规格、实测值和推测值保持区别。基线未知时不从模组尺寸或理论焦距代填。
- 后续按实现需要建立采集、标定、匹配和评估 JSON 配置。运行配置引用设备标识及标定文件，避免复制整份硬件档案；引用配置不匹配时明确报错。
- 调用层解析配置、校验类型及必要字段后调用核心函数；核心函数不访问设备、不解析 Markdown、不依赖全局配置。采集适配层负责设备 IO，离线与相机入口复用同一重建函数。
- 建立有类型的 `capture_pairs`、`calibrate_stereo`、`build_rectification`、`reconstruct_pair`、`evaluate` 接口。实际签名在 A0 细化，输入输出含义遵循算法规格；若接入 function calling，再单独声明工具参数 schema 与适配层。

### 图像与采集记录

- 适配层统一输出左右身份明确、同尺寸的 BGR `uint8` 图像，形状 `(height, width, 3)`；原始双目对以无损 PNG 保存，不做未记录的缩放或裁剪。
- `pairs.csv` 使用算法规格的字段：`pair_id,left_path,right_path,left_read_time_ns,right_read_time_ns,width,height`。路径相对该 CSV 所在目录解析；宽高为拆分后的单目尺寸。
- 双设备使用先 `grab` 后 `retrieve` 的成对读取；单设备左右拼图由适配层拆分，并记录原始模式和左右顺序。同一拼图两侧的读取时间可相同，单独说明其含义；读取时间不代表曝光同步时间。
- 采集记录补充设备身份、实际分辨率、模式、控制设置与失败原因。左右均成功才登记完整图像对；退出时释放设备。
- 标定、校正独立验证和距离测试数据分开标记；同一基线与相对姿态绑定一套标定，改变后旧标定失效。

### 算法产物与单位

- 标定保存 `calibration.npz`，至少包括算法规格规定的 `K1,D1,K2,D2,R,T`、图像/棋盘格尺寸、格长、RMS，以及有效配对、库版本记录；图像尺寸顺序为 `(width,height)`，距离为米。
- 校正保存 `rectification.npz`，包含映射表、`R1,R2,P1,P2,Q` 和 ROI；对应输入分辨率与标定身份可追溯。
- 输出像素单位 `float32` 视差、米单位 `float32` 深度、布尔有效掩码和彩色 ASCII PLY；深度无效值用 `NaN`。可视化图不参与数值计算。
- `metrics.json` 记录汇总与配置/环境；`samples.csv` 记录逐样本结果、参考距离、固定 ROI 和失败原因；耗时以毫秒标注。
- 大型数据与运行产物遵循 `.gitignore`，通过采集/生成步骤和受团队访问控制的数据位置复现；文档保留数据标识和证据位置，不依赖某个人机器上的绝对路径。

## 5. 硬件路线

### H1：确认设备与输出模式

状态：待开始；依赖：设备可用及宿主机访问权限。

工作：核实单 UVC 拼图还是双 UVC；确认左右顺序、实际输出尺寸、格式、连续读取帧率及手动控制支持情况。探测结果形成记录，尚未核实的参数保持未知。

验收：可追溯的设备信息与样图；连续 300 帧的成功/失败和帧率统计；明确采用哪种采集适配方式。帧率实测不等同于规格书上限。

### H2：固定双目结构与控制成像

状态：待开始；依赖：H1。

工作：设定基线、保持刚性并记录光心距；锁定曝光、增益与白平衡，记录实际可设置值。不能手动锁定时记录限制并判断静态采集是否可继续。

验收：安装/基线记录、锁定状态与控制配置可复现；实测结果进入配置或实验记录，历史基线记录不覆盖。

### H3：交付标定、验证和距离测试数据

状态：待开始；依赖：H2；可与 A1–A4 并行。

工作：测量棋盘格内角点行列数及 `square_size_m`；采集不同位置、距离、倾角的配对，先以至少 15 对有效标定图为起点，另留独立验证图。采集静态纹理场景及至少三个距离段的正面纹理平面，每段重复采集并记录参考距离与测量方式。

验收：PNG 与 `pairs.csv` 满足契约；左右角点身份一致；标定数据和评价数据明确分开；独立参考能换算到校正后左相机光心与前向轴。有效标定对数由角点检测确认，单凭保存数量不算通过。

## 6. OpenCV 软件路线

### A0：环境、配置校验与离线入口

状态：待开始；依赖：无硬件依赖。

工作：建立 Python 3.11 环境与依赖清单，固定可用 OpenCV、NumPy 版本；建立 `src/`，细化有类型的接口、配置校验、配对读取及 CLI 入口。函数说明明确数组元素类型、形状、单位和失败方式。

验收：可复现安装并导入依赖；离线入口能读取一对输入；缺文件、图像尺寸不符、缺必要字段及非法参数有明确错误。真实硬件的未知状态不会阻止独立的离线输入验证。实现后将实际运行命令登记在 README 中。

### A1：离线双目标定与参数保存

状态：待开始；依赖：A0；真实验收依赖 H3。

工作：按算法规格进行角点检测和亚像素精化，任一侧失败则整对拒绝并记录原因；左右单目标定后固定内参求双目外参，保存参数、有效配对、RMS 和环境信息。

验收：参数保存并重载后保持一致，参数有限且基线为正；左右角点顺序一致；逐帧和汇总重投影误差可追溯。合成输入的已知几何用于检查约定，真实拟合质量单独记录。

### A2：去畸变与极线校正

状态：待开始；依赖：A0 和兼容标定，端到端真实标定来自 A1。

工作：按算法规格使用零视差、原尺寸校正，保存映射表、投影矩阵、`Q` 与 ROI；输出水平辅助线预览，匹配输入保持干净。

验收：重载参数可校正相同尺寸图像；验证水平布局、有效区域和尺寸一致性；独立棋盘格对应角点的垂直残差报告均值与 P95。后续不额外改变图像尺寸破坏 `Q`。

### A3：视差、深度、有效掩码与点云

状态：待开始；依赖：A0、A2 或已说明约定的校正样例与匹配参数。

工作：使用 OpenCV SGBM，校验搜索范围、块大小及惩罚参数；定点视差除以 16 后重投影；结合几何搜索有效 ROI、合法视差、有限三维坐标与正深度构建掩码。导出数值数组、预览和 RGB 彩色 PLY。

验收：已知视差与几何样例能检查尺度、符号及单位；无效点不进入点云；PLY 可读取且点数等于掩码有效点数；全部无效或 ROI 为空时明确报错。合成尺度检查不替代真实相机误差评价。

### A4：评估与复现记录

状态：待开始；依赖：A1–A3 的输出及对应评价输入。

工作：输出左右重投影 RMSE、独立校正垂直残差、距离 MAE/RMSE/相对误差、固定 ROI 覆盖率、重复性和分阶段耗时。记录总样本数、成功/失败数及计时范围；参考距离和 ROI 从配置/数据记录传入。

验收：已知结果可核对指标，失败样本不会以零混入均值；没有真实参考时距离精度明确标记“未评估”。同输入与配置可以重复生成 `metrics.json`、`samples.csv`；计时注明设备、分辨率、视差范围、平均值与 P95，不将算法耗时称为完整采集帧率。

## 7. 汇合与阶段验收

### I1：真实采集数据贯通

状态：待开始；依赖：H3 与 A1–A4 的必要处理能力。

用真实数据完成标定、独立图像校正、重建和基础评估。再次核对设备标识、基线、分辨率与标定是否匹配；将离线重建函数复用到采集入口。保留原始图像、配置引用、标定/校正文件、数值结果、有效掩码、PLY、预览与运行记录。

验收：一条记录明确的复现路径能重新生成完整输出；设备失败和样本失败可追踪。可视化正常只表示基础检查通过。

### I2：独立距离评价与完成报告

状态：待开始；依赖：I1、独立参考与重复采集。

按至少三个距离段进行评价，核对参考坐标、固定 ROI、覆盖率和重复性。允许的重投影误差、垂直残差、测距误差及覆盖率阈值在正式精度验收前写入评估配置；未确定阈值时报告实测值并将精度结论标记“未判定”。

完成条件：H1–H3、A0–A4、I1–I2 均有相应验证证据，真实数据流程可复现，独立距离评价完成，失败与限制记录完整。基础流程完成与使用精度达标分别给结论；没有阈值或指标未达标时不能宣称精度达标。如核心交付仍缺失，计划继续保留在 `active/`。
