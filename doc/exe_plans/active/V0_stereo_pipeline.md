## 1. 目标与范围

使用 Python 3.11、OpenCV 和 NumPy，建立“原始双目图像 → 标定 → 校正 → SGBM 视差 → 深度与彩色点云 → 评估”的可复现流程。先支持保存图像的离线处理，再接入真实相机；图像数组、标定参数和配置通过明确的函数接口传递。

本阶段处理固定结构、固定分辨率、水平双目下的静态场景。不扩展学习式匹配、置信度网络、在线自适应、多帧融合、网格重建或 SLAM。

## 3. 并行路线与依赖

```text
                    对齐图像、配置与标定契约
                         /          \
硬件路线：H1 设备确认 → H2 固定与控制 → H3 数据采集
软件路线：A0 环境接口 → A1 离线标定 → A2 校正
                                      → A3 重建 → A4 评估
                         \          /
                  I1 真实数据联调 → I2 独立评价与复现
```

硬件路线由持有设备的协作者与采集适配实现共同推进；本 Agent 负责软件路线及后续算法联调。两条路线可由不同成员并行，不要求同一工作区同时修改同一配置文件。

A1–A4 可以先使用明确来源的离线样例或标记为合成的数据验证程序行为。没有真实棋盘格时，可以验证标定调用、序列化及失败处理，但真实标定质量保持待验证。使用外部数据时保留来源、使用条件、图像处理方式与标定约定，避免把已校正图重复校正。合成验证结果不用于宣称本设备测距精度。

H3 与软件路线通过共享格式对接；硬件不阻塞算法开发，但 I1 需要 H3 与 A1–A4 的必要能力，I2 还需要独立参考距离数据。

## 4. 两条路线的交付契约

### 配置与接口

- `config/hardware.json` 当前为 schema v2.1，维护相机参数与已知状态；厂商规格、实测值、推导值和推测值保持区别。`document.sources` 记录规格页与 SHA256，分组 `source`/`raw` 记录来源和原文，`uncertainties` 记录 U1–U8（统一 `status: pending`，含 `target_fields` 与 `resolution` 预留字段），`pending_summary` 汇总未决项，`ai_usage` 给出读取顺序与硬约束。基线未知时不从模组尺寸、图纸尺寸或理论焦距代填。
- 读取层应校验 `schema_version`、单位、分辨率数组顺序与必需字段；遇到 `null` 或 `uncertainties` 中 `status: pending` 项时明确报错或要求实测，不能静默套用默认值。`resolution.value` 未填写时不得当作已确认数据。`calibration.nominal_focal_px` 只做 sanity check，不能替代标定结果。
- 后续按实现需要建立采集、标定、匹配和评估 JSON 配置。运行配置引用设备标识及标定文件，避免复制整份硬件档案；引用配置不匹配时明确报错。
- 调用层解析配置、校验类型及必要字段后调用核心函数；核心函数不访问设备、不解析 Markdown、不依赖全局配置。采集适配层负责设备 IO，离线与相机入口复用同一重建函数。
- 建立有类型的 `capture_pairs`、`calibrate_stereo`、`build_rectification`、`reconstruct_pair`、`evaluate` 接口。实际签名在 A0 细化，输入输出含义遵循算法规格；若接入 function calling，再单独声明工具参数 schema 与适配层。

### 图像与采集记录

- 适配层统一输出左右身份明确、同尺寸的 BGR `uint8` 图像，形状 `(height, width, 3)`；原始双目对以无损 PNG 保存，不做未记录的缩放或裁剪。
- `pairs.csv` 使用算法规格的字段：`pair_id,left_path,right_path,left_read_time_ns,right_read_time_ns,width,height`。路径相对该 CSV 所在目录解析；宽高为拆分后的单目尺寸。
- 双设备使用先 `grab` 后 `retrieve` 的成对读取；单设备左右拼图由适配层拆分，并记录原始模式和左右顺序。同一拼图两侧的读取时间可相同，单独说明其含义；读取时间不代表曝光同步时间。
- 采集记录补充设备身份、实际分辨率、模式、控制设置与失败原因。左右均成功才登记完整图像对；退出时释放设备。
- 标定、校正独立验证和距离测试数据分开标记；同一基线与相对姿态绑定一套标定，改变后旧标定失效。

### 算法产物与单位

- 标定保存 `calibration.npz`，至少包括算法规格规定的 `K1,D1,K2,D2,R,T`、图像/棋盘格尺寸、格长、RMS，以及有效配对、库版本记录；图像尺寸顺序为 `(width,height)`，距离为米。
- 校正保存 `rectification.npz`，包含映射表、`R1,R2,P1,P2,Q` 和 ROI；对应输入分辨率与标定身份可追溯。
- 输出像素单位 `float32` 视差、米单位 `float32` 深度、布尔有效掩码和彩色 ASCII PLY；深度无效值用 `NaN`。可视化图不参与数值计算。
- `metrics.json` 记录汇总与配置/环境；`samples.csv` 记录逐样本结果、参考距离、固定 ROI 和失败原因；耗时以毫秒标注。
- 大型数据与运行产物遵循 `.gitignore`，通过采集/生成步骤和受团队访问控制的数据位置复现；文档保留数据标识和证据位置，不依赖某个人机器上的绝对路径。

## 5. 硬件路线

### H1：确认设备与输出模式

状态：待开始；依赖：设备可用及宿主机访问权限。

工作：核实单 UVC 拼图还是双 UVC；确认左右顺序、实际输出尺寸、格式、连续读取帧率及手动控制支持情况。对应 JSON 的 U2（最大分辨率/模式表）、U4（设备拓扑/左右顺序）、U5（UVC 推断）、U6（手动控制）、U8（实际帧率）。探测结果形成记录，尚未核实的参数保持未知。

验收：可追溯的设备信息与样图；连续 300 帧的成功/失败和帧率统计；明确采用哪种采集适配方式。帧率实测不等同于规格书上限。

状态：待开始；依赖：H1。

工作：设定基线、保持刚性并记录光心距（U3）；锁定曝光、增益与白平衡，记录实际可设置值（U6）。不能手动锁定时记录限制并判断静态采集是否可继续。基线改变后不要复用旧标定。

验收：安装/基线记录、锁定状态与控制配置可复现；实测结果进入配置或实验记录，历史基线记录不覆盖。

### H3：交付标定、验证和距离测试数据

验收：PNG 与 `pairs.csv` 满足契约；左右角点身份一致；标定数据和评价数据明确分开；独立参考能换算到校正后左相机光心与前向轴。有效标定对数由角点检测确认，单凭保存数量不算通过。
