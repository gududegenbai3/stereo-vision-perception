# 硬件与接口：HBVCAM-4M2403HD V22

> 本文档是本项目摄像头硬件的**人类可读说明**；机器可读字段独立维护于 `config/hardware.json`。
> 参数来源：厂商规格书第 3 页（Key Specifications）和第 4 页（Module Mechanical Dimension），版本 A，日期 2024-10-30。
> 用户确认：采购的是 **80° 无畸变版本**；两个摄像头之间是**软连接**，基线可调。
> 最后核对：2026-10-17。

## 1. 独立硬件配置

硬件配置已提取至 [`config/hardware.json`](../../config/hardware.json)，作为机器可读参数的唯一维护入口。本文负责解释字段、使用约束与实测流程，不再内嵌 YAML 或重复维护规格参数表。

配置保留原有字段分组：

- `rig_id`、`vendor`、`model`、`user_description`：设备身份。
- `document`：规格书来源与版本。
- `interface`、`sensor`、`lens`、`mechanical`：接口、传感器、镜头和机械规格。
- `output`：输出格式、默认自动控制状态与 `supported_modes` 分辨率/标称帧率列表。
- `stereo`：基线、安装、锁定状态与左右目布局。
- `calibration`：标定状态与理论焦距参考。

## 2. 配置数据与调用边界

- JSON 中数值、布尔值和数组保留各自类型；未知数值保持 `null`，不以零或猜测值替代。已有 `unknown` 状态字符串表示尚未确认。
- 带 `_mm`、`_um`、`_nm`、`_px`、`_c` 等后缀的字段按字段名中的单位解释；分辨率数组按 `[width, height]` 排列，模组尺寸按规格书原顺序保留。`max_fps` 为标称最大帧率，不是实测帧率。
- 物距、供电范围、滤光片范围等原始复合规格仍保留为字符串，不直接当作数值运行参数。`notes`、`nominal_focal_note` 等是配置附带的来源说明，不参与数值计算。
- 畸变冲突和理论焦距按原始资料保留；`likely_value` 不是已确认的畸变参数，`nominal_focal_px` 不能替代真实标定焦距。规格中最大分辨率与模式列表存在的差异仍保留，实际可用模式由设备验证。
- 本文件是硬件档案配置，不包含已验证的相机编号、曝光设置或标定结果。读取该 JSON 不代表设备可直接运行；需要的实测参数缺失时，调用层应给出明确错误。
- 后续代码由配置读取层解析 JSON、校验类型与必要字段，再把参数传给有类型声明的函数；核心算法不读取 Markdown，也不隐式读取全局配置。若暴露为 function calling 工具，工具名称、参数 schema 与实现适配层另行声明，不能把本配置直接当作工具定义。

## 3. 输出模式与采集建议

完整模式列表见 JSON 的 `output.supported_modes`。这些值来自规格书的“Maximum Image Transfer Rate”，实际帧率受 USB 带宽、曝光时间、主机和驱动影响。

- 第一阶段优先使用 MJPG；高分辨率 YUY2 的标称帧率较低。
- 在确认单设备左右拼图后，可优先尝试总尺寸 2560 × 720 或 1280 × 480，再根据处理速度提高分辨率。这是采集建议，不是已确认的运行配置。
- 仅在左右拼图模式下，总图像宽度才等于单目宽度的两倍；双独立设备模式以各设备实测尺寸为准。

## 4. 双目相关的关键未知项

这些参数不能从规格书直接推定，必须接入后实测：

| 未知项 | 为什么重要 | 如何确认 |
|---|---|---|
| 光学基线 | 可调，直接决定深度范围和误差；每次改变都会使旧标定失效 | 设定后用卷尺/卡尺量两个镜头光心距离，锁死并记录 |
| 左右目排布 | 决定 `mode: dual` 还是 `side_by_side` | 用 `probe` 看设备数量；看画面是否左右拼图 |
| 单目分辨率 | 决定 SGBM 的搜索范围和速度 | 逐档设置并读取实际分辨率 |
| 左右目顺序 | 接反会导致视差符号和深度异常 | 用有明显前后关系的场景确认 |
| 手动曝光/增益/白平衡 | 不锁定会导致两帧亮度漂移，结果不可复现 | 用厂商软件或 UVC 控制工具检查 |
| 实际可用帧率 | 规格书是上限，USB 带宽可能更低 | 连续读 300 帧统计 |
| 第 3 页 TV Distortion 的 `<97.2%` | 与第 4 页 `<3%` 冲突 | 向供应商确认，或实测畸变 |

特别提醒：**143.6 mm 是模组整体尺寸，不是已经确认的光学基线。** 不能直接把模组长度写进深度公式。

| 日期 | 基线 mm | 连接/锁定方式 | 是否锁死 | 标定文件 | 备注 |
|---|---:|---|---|---|---|
| 2026-10-17 | 待测 | 软连接 | 否 | 尚未标定 | 初次接入，范围和锁紧方式待确认 |

规则：

- 同一行基线记录对应一套标定结果。
- 改变基线后必须重新标定，不能复用旧 `calibration.npz`。
- 建议 `rig_id` 带基线值，例如 `hbvcam-4m2403hd-v22-b80mm`。
- 运行 manifest 中记录本次实际使用的 `baseline_mm`。

## 6. 对算法和采集的影响

1. **“80° 无畸变”不等于不需要标定。**  
   低畸变镜头仍然需要标定内参、外参和极线校正。标定结果应保存到 `data/calibrations/<rig_id>/`，不要手写进本文档。

2. **默认 Auto 曝光是复现性的风险。**  
   规格书写的是 AEC/AGC/白平衡 Auto。正式采集前必须确认能否手动锁定；如果只能自动，需要在报告中记录这一限制。

3. **卷帘快门不适合快速运动场景。**  
   静态标定和静态深度演示没问题；运动目标可能产生时间错位。第一阶段先用静态场景。

4. **USB 2.0 高分辨率优先用 MJPG。**  
   3840 × 1080 的 MJPG 标称 30 fps，YUY2 只有 1 fps。不要用 YUY2 做实时双目。

5. **理论焦距只能做 sanity check。**  
   由 `EFL / pixel_size` 得到约 1500 px，但实际焦距会受镜头、分辨率和标定影响。深度计算以 `calibration.npz` 中的 `P1[0,0]` 为准。

6. **基线未知时不要宣称米级精度。**  
   在完成物理测量和双目标定前，只能输出“近似深度热力图”，不能把结果当作测距精度。

7. **基线可调意味着标定不是永久的。**  
   软连接允许调整基线，但运行和拍摄期间必须保持刚性、锁死。每次改变基线或左右目相对姿态后，旧标定立即失效，必须重新标定。建议在 `rig_id` 或标定目录名中带上基线值，例如 `hbvcam-4m2403hd-v22-b80mm`，并在 `manifest.json` 中记录本次运行使用的 `baseline_mm`。

8. **软连接不等于软同步。**  
   如果最终是两个独立 USB 摄像头，左右目是两路独立视频流，需要确认是否在同一帧循环读取，以及两路曝光是否能同时锁定。若两路自动曝光不同步，亮度漂移会直接破坏 SGBM 匹配。

## 7. 接入后的检查顺序

```text
1. 确认设备数量：一个 UVC 设备还是两个 UVC 设备
2. 确认画面：单路宽画面，还是左右拼图
3. 确认分辨率：实际输出宽度、单目宽度、FPS、FOURCC
4. 确认左右目顺序
5. 锁定曝光、增益、白平衡
6. 设定基线，锁死软连接，测量光心距
7. 记录基线值和连接方式
8. 采集棋盘格图像对
9. 双目标定，记录 RMS 和基线
10. 跑 SGBM，输出深度热力图
```
