# URS-Stereo: Uncertainty-Guided Residual Search for Real-Time Stereo Matching

> arXiv 2607.06779 ｜ Sohrabipour, Pallerla, Wang ｜ 2026-07 ｜ 本仓库标签：`锚点-先行工作`

## 它解决什么问题

实时（coarse-to-fine）立体匹配依赖上一阶段传播的视差作为下一阶段的搜索中心。一旦传播值不准，真实对应点会落到预定义的局部搜索范围之外，后续精化无法恢复（不可逆的匹配失败）。作者指出这是"搜索范围固定"带来的结构性缺陷，而不是特征能力不足。

## 方法核心

1. **UGRSM（Uncertainty-Guided Residual Search Module）**：同时预测两件事——传播视差的可信度，以及相对当前中心的**残差搜索偏移**。
2. 用可信度**动态重新定位局部代价体的中心**，再在该局部范围内做精化；搜索范围本身不扩大，只是"移到更可能对的位置"。
3. 保持 coarse-to-fine 的计算量级，因此仍是实时方法。

## 关键结论

- 在 SceneFlow / KITTI 2012 / KITTI 2015 / Middlebury / ETH3D 上一致提升视差质量，同时保持实时速度。
- 说明了"不确定度"在立体匹配里的一个具体用法：**不是用来扔掉不可靠像素，而是用来决定下一轮去哪里找**。

## 与本项目的关系

- 对应本项目 **分配（B 模块）**这一步，但调的是"搜索范围/中心"这一个维度；
- 本项目的差异点：把不确定度用于**预算约束下的像素级挑选**（算哪里、算多少），并在实物上测开销；URS-Stereo 不做预算扫描、不测能耗、不区分"可救/不可救"；
- 引用时可用于支撑"用不确定度指导计算分配是有效方向"，同时说明本项目在"分配维度 + 开销口径"上的不同。

## 风险

1. 无法直接复现 → 只能作为相关工作总结，不能作为实验对照；
2. 其"不确定度"定义与我们的 LRC 不同（网络内部预测），直接搬用需要训练，不适合本作业的算力条件；
3. 若照抄"用不确定度调搜索范围"作为创新点，会被这篇直接盖住——本项目必须把落点放在"预算化挑选 + 开销测量"上。
